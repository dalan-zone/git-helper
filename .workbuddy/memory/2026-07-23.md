## Built: Android Gradle 模板（version catalog + CI 自动升号）
在空工作区 `git-helper` 从零搭了一套可复用的 Android 工程骨架，落地"版本管理最佳实践"：

- 版本双轨制：`versionName`(SemVer) 在 `gradle.properties` 由人改；`versionCode` 自动推导，优先级 CI env VERSION_CODE → version.properties → git commit count（`app/build.gradle.kts` 的 `computeVersionCode()`）。
- 依赖/插件集中到 `gradle/libs.versions.toml`（Version Catalog），root `build.gradle.kts` 仅 alias 声明。
- 多环境用 `productFlavors`（dev/staging/prod）经 `buildConfigField` 注入 BASE_URL，自动加 applicationIdSuffix。
- CI：`.github/workflows/release.yml` 打 tag vX.Y.Z 或手动触发，自动 versionCode+1、构建 prodRelease AAB、回写 version.properties；含 Play 上传注释步骤。

## Bug 修复：computeVersionCode 编译失败（用户构建时报 5 个错）
`.gradle.kts` 顶层 `fun` 实为脚本局部函数，导致：
1. lambda 内 `return` 不被允许（"return is not allowed here"）—— 改为函数体层级的 `if (x != null) return x`。
2. `java.util.Properties` / `java.io.ByteArrayOutputStream` 报 "Unresolved reference: util/io" —— 需在脚本顶部显式 `import java.util.Properties` 与 `import java.io.ByteArrayOutputStream`，不能直接用全限定名（脚本默认未导入 java.* 子包）。
经验：在 .gradle.kts 里写顶层函数时，避免 lambda 内 return，且 Java 类要 import。
